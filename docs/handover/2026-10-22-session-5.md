## Learned the hard way

- Linux Chromium on GitHub's runners measures layout shifts Windows hides: a web font arriving after first paint moved `<main>` (CLS 0.128 on `/ar/sources` and `/ar/privacy`) because the 600 face was not preloaded; the 147-row credits table also pulled two Inter subsets through Cyrillic author names. Preload every Arabic face a page draws above the fold; keep reference tables in the system font.
- An Arabizi word can be wider than a phone: "khousousiya" at the h1 size is 324 px, over the 288 px a 320 px screen leaves; the 320 px e2e test catches it. Prefer short words in titles.
- A validator that derives a value (the fame tier from the score) makes a threshold change a data change too: retier `pool.json` in the same pull request.
- The nightly workflow's `pull_request` CI run shows `action_required` for the bot's pull request; the job's own `workflow_dispatch` run is the one that counts. After merging a fix into `main`, `gh api -X PUT repos/JalelDridi/kora/pulls/N/update-branch` merges main into a pull request branch without touching the local tree; then dispatch `ci.yml` on `data/nightly` by hand.
- The witness backfill matches national-football-teams pages by a guessed name when the country page gives no link; after 156 such pages the caps "differs" rate jumped to 45% (stop rule tripped). Verify the player on the page (birth date or name) before judging a guessed page.
- fast-check with Vitest 5: an expression-bodied property returning `expect(...)` is read as "returned false"; use a block body.
- Never dispatch a reviewer while switching branches in the same tree; do small controller pull requests between tasks, on branches from `main`, then return to the sprint branch.
