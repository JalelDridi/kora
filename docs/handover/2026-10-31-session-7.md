## Learned this session

- A source can change under the pipeline without any source being "stale": the English infobox stopped giving `currentclub` on 26 October and the pool bled 2 to 13 actives a night for five nights; the shrink guard counted footballers, not clubs or actives. Guard the derived counts you care about (actives, clubs becoming none), compare with main's pool, and read the "Club changes" list of every nightly pull request before merging.
- Rewriting commit messages with `git filter-branch` drops the SSH signature; follow it with `git rebase --exec "git commit --amend --no-edit --reset-author" <base>` to re-sign. Implementer agents may refuse the house trailer; the controller sets it.
- Tests that measure layout must be able to fail: a CLS bound of 0.1 never catches a 24 px shift, `splitWords` never sees an ellipsis, a 6-Tab parity check never sees focus leaving. Assert the exact position, the overflow (`scrollWidth > clientWidth`) and the focus after every press, and remove the guard once to watch the test go red.
- A data-driven layout test ("every value the pool can show fits its column") turns a new club in the nightly pool into a CI failure on the nightly pull request: give the layout an automatic fallback and let `data:check` warn, so curated labels are a nicety, not a gate.
- Tailwind 4's `rtl:` variant also matches `:lang(ar)`, so it fires on the Arabizi page (`ar-Latn-TN`): use `[[dir=rtl]_&]:` or logical utilities.
- Native `<dialog>` with `showModal()` keeps the page inert but lets Tab leave a dialog with a single focusable control: keep a small Tab wrap.
- next/og, picomatch, the Facebook in-app browser and the Lighthouse seed lessons of session 6 still hold.
