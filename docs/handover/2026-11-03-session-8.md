## What shipped

- **`/admin`, a dashboard home**: today's and tomorrow's Chkoun? answer, the pool's counts, what to review, the last rebuild, whether GitHub is connected and when the token runs out, quick links. A nav of eight places on every admin page.
- **The footballer editor** (`/admin/footballers/<Wikidata id>`): every override field with today's value and its source, a preview of the diff and the commit message, then Save: one commit on `main` to `data/overrides.json`. Exclude, Include again, local star.
- **Add a footballer** (`/admin/add`): search Wikidata, see whether the result is a footballer and Tunisian, add him with a note: an `include` override; the nightly then fetches him (the pipeline's three footballer queries take the included ids).
- **Game views**: `/admin/games/chkoun` (active, answer-ready, one field away, fame short, in grace, tiers; a local-star form beside the fame-short footballers) and `/admin/games/season` (each Ligue 1 club's candidates and ratings).
- **Settings** (`/admin/settings/<file>`): the six curated files, one row at a time, each save checked by `data:check`'s rules first.
- **Rebuild now** (`/admin/rebuild`): dispatches the nightly workflow with `merge_when_green`; the page follows the run, a guard's refusal, the pull request, CI and the merge, reloading every 15 s with a switch to stop. The workflow arms auto-merge only when `main` requires CI's check (T-AD-9).
- **Changes** (`/admin/changes`): the last 30 commits to the data files; a dashboard commit can be undone, as a new commit, entry by entry.
- Tests: unit and database tests per module; browser tests per page, one story across the whole round at 360 px (add, a club, a local star, a strength, rebuild, the log, undo, with `data:check` after each commit), and security checks (every admin page and action is 401 without the password; no admin page carries the token's stand-in or `Bearer`; no browser file holds admin code). Screenshots at 360 and 1280 px of every page and state were sent to Jalel; they stay in the session's container and are not in the repository.

## Once, in the settings (Jalel)

1. GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token: repository `JalelDridi/kora` only; Contents, Actions and Pull requests read and write; Metadata, Checks and Commit statuses read; one year.
2. Vercel → the project → Settings → Environment Variables: `KORA_GITHUB_TOKEN`, Production only, Sensitive; redeploy Production.
3. GitHub → the repository → Settings → General → Pull Requests: tick Allow auto-merge.
4. A ruleset on `main` requiring the check `check`, with Repository admin allowed to bypass (T-AD-9, `data/README.md`, "Auto-merge"), before the first real rebuild: without it a dashboard rebuild opens its pull request with auto-merge off and says so.

## Try first, on your phone (15 minutes, after the token is set)

1. Open `/admin`: the GitHub card says connected, with the token's expiry.
2. Mark someone harmless a local star with a note (from `/admin/games/chkoun`, "Answer-ready, fame short", or his editor), save, and see the commit on GitHub (`data(overrides): …`, `Admin-Edit: overrides`).
3. Undo it from `/admin/changes` and see the revert commit.
4. Rebuild now and watch the stages to "Merged" (or "No change").
5. Open `/admin/games/chkoun` and check today's answer matches the game.
